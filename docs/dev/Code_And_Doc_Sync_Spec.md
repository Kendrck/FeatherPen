# FeatherPen/docs/dev/Code_And_Doc_Sync_Spec.md
# GB/T 8567 代码与文档同步强制规范
## 总则
STRUCTURE.md、API_MODULE_SPEC.md 为项目唯一基准文档，所有源码、目录变更必须以两份文档为准；代码必须对齐文档定义，仅改代码不更新文档、代码与文档参数/名称不一致均判定交付无效。
## 一、文档强制规范
1. STRUCTURE.md、API_MODULE_SPEC.md 首固定板块为 File Path_完整三级文件结构树；
2. 目录树每条条目格式：完整文件路径+后缀 + 标准化功能注释；
3. API_MODULE_SPEC 统一归档：文件路径、占用端口、导出函数、HTTP接口、编码命名、废弃清单；
4. 两份文档均设置【全局废弃黑名单】，统一登记废弃目录/函数/接口/硬编码；
5. 新增/修改/删除任意文件、函数、端口、接口，必须同步更新两份架构文档，缺一不可。
## 二、源码开发标准执行流程（顺序不可调换）
1. 查阅基准：修改前先读取 API_MODULE_SPEC.md，完整复制文档登记的函数名、接口路径、端口、模块名称，禁止凭记忆手写、自定义简写；
2. 编写源码：单个文件独立覆盖，文件首行注释以 FeatherPen/完整路径开头；仅保留源码+国标业务注释，删除调试/迭代/临时/废弃代码，零冗余；函数、核心逻辑配套标准注释，无草稿备注；目录层级遵循GB/T 8567，一二级目录锁定不可增删重命名，仅允许三级拓展；
3. 全局校验：代码编写完成后全局检索文档标记废弃关键词（如 load_config、db_get_user_info），清理所有残留废弃调用；
4. 同步文档：新增文件需完整录入两份文档目录树并补充功能注释；修改参数/函数同步更新对应文档条目；删除文件移入废弃黑名单归档。
## 三、硬性命名规则（严格复刻文档登记文本）
1. Python：函数 snake_case，类 PascalCase，常量全大写；
2. JS：函数 camelCase，常量全大写；
3. HTTP：GET查询、POST提交、PUT更新、DELETE删除，接口路径一字不差与文档一致；
4. 端口禁止硬编码数字，统一读取config.yaml，配置名与文档对齐。
## 四、交付校验清单
[√] 函数、接口、端口名称与API_MODULE_SPEC完全一致，无简写手写差异
[√] 全局无文档标记废弃函数/字符串残留
[√] 新增/改动文件同步更新STRUCTURE、API_MODULE_SPEC目录树
[√] 所有源码首行标注FeatherPen完整文件路径注释
[√] 源码无调试、临时、废弃冗余代码
[√] 目录层级符合GB/T 8567，一二级目录未改动
[√] 物理文件、STRUCTURE目录树、API_MODULE_SPEC三者完全匹配
## 五、违规判定
出现以下任意一条，改动无效，禁止打包、合并、交付：
1. 函数名、接口、端口与文档定义不一致；
2. 新增物理文件未录入两份架构文档；
3. 代码存在黑名单废弃函数调用；
4. 仅修改源码，未同步更新STRUCTURE.md、API_MODULE_SPEC.md。
